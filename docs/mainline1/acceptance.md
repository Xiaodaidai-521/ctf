# 验收基线 v1（Proposed）

本轮冻结可审阅的验收内容和统计口径，不虚构效果门槛。第2步时业务验收均Untested；2026-10-13第3步实测范围更新见下表，不能将草案校验算作功能实现测试。14个核心对象覆盖不是功能覆盖率。基线来自完整提示词 D/F/J 和第1步 E03—E13。

## 实验设计和数据隔离（第9步，当前未执行）

建立两套分开的数据：固定功能样本供开发回归；独立效果集供最终A/B/C。只使用合成数据；人工按预定义类别/关系/政策标注，不让被测模型生成等级真值。数据清单须含 dataset_version、generator/template_family、business_entity_group、文件摘要、annotation_version、policy_version、split、freeze时间、标注争议处理记录。含定位的标签绑定 asset_version/sheet/row/column/channel/span，不只标文本。

切分单位是模板族与业务实体组，先分组再生成或分配样本。训练/提示开发/验证/最终测试的组不能相交；仅换姓名数字仍同组。样本规模与各类最小支持量在真实实验前登记，当前 Unknown，不编造样本数。冻结最终测试清单后不得根据结果反复调整标签/阈值/提示；标注确有错误时保留旧版本及修订理由，另报受影响结果。类别缺样本单独披露，不能藏入汇总。

A：固定规则基线；B：同A规则＋相同目标列样本语义；C：同B再加入表头、相邻字段、业务说明。若规则使用表头三组保持相同。目标单元格集合、解析、规则、模型/参数/修订、seed、目标文本字节/码点范围固定。C附加上下文不能挤掉目标内容；必要时优先删附加上下文，并记录输入/截断。无法保证目标等价则报告比较限制，不把差异当纯上下文贡献。

每组记录目标总量、实际目标清单、各层processed/skipped/failed、模型调用次数/错误、模板版本、token（不可获得则null而非估算冒充实测）、输入长度、截断数量、采样种子、延迟与可测费用。缓存策略三组一致并单列命中，不能A冷启动C复用结果而不披露。无固定模型修订记录可复现限制。C对B仅支持附加上下文整体效果；单因素贡献需要另设单因素消融，不强制所有组合。

## 匹配与指标口径（预登记，无数值效果门槛）

- 字段分类单位：固定资产版本+sheet+column。多类别视为多标签，按(category,column)二元项统计；抽样只能证明该列建议，不能计全量实体召回。
- 文本实体单位：固定资产版本+sheet+row+column+channel+精确[start,end)+category。主指标严格完全匹配，预测去重后采用一对一匹配。重复预测额外计FP；可另报区间IoU辅助指标，但不混入严格主指标。规则/语义/人工来源分组，人工纠正不能倒灌自动检测效果。
- 组合单位：预标注relation_type+排序成员位置/类别集合；精确关系一对一匹配。组合真值与普通实体分开，未知关系不强行当负例。
- TP/FP/FN在冻结标签单位上计数。Precision=TP/(TP+FP)，Recall=TP/(TP+FN)，F1=2TP/(2TP+FP+FN)。对应分母0返回null及原因；有真值但无预测，Recall/F1=0而Precision=null。Macro-F1对有真值支持的冻结类别求均值，同时逐类展示无真值类别的预测FP和F1/null情况，不靠排除困难类别美化；报告included/excluded类别数。
- 失败/未解析/未扫描样本仍留总清单。有明确真值的漏覆盖产生FN；负例失败不能计为成功TN，同时进入failure/coverage统计。证据不足/待复核/拒答不从总集删除；另报自动判定子集及其原总体分母。
- 等级映射正确率按已有分类证据能确定等级的样本计算，冻结政策版本；无法确定类别的单独unknown，不让模型自行提供“正确等级”。
- 分层覆盖按每层固定 unit 分开，比例=processed/target；target未知/0则null且原因明确。人数未知保持null。评估实际解析失败率=失败资产数/总目标资产数，模型失败率=失败调用数/总调用数；两者不能混合。
- 自动处理覆盖=无需复核且有有效判定的目标单位/全部目标单位；复核率/拒答率按同一预定单位分开（列/实体任务），同一单位只计一次；子集质量附覆盖分母。不指外发已自动批准。
- 延迟用每次扫描墙钟与模型调用分开，报告样本数、均值和可计算的分位数；成本仅报告接口usage与已批准价格基线可推导/实测值，无法取得为null，不编造费用。

效果门槛：会话和仓库未提供有效数值目标，故 Unknown；报告真实值、误报/漏报/未知/降级案例与局限，不在观察结果后补造达标线。合成效果不外推生产表现。真实后端缺失时核心A/B/C实验为Blocked，不能用Mock代替。

## 本步草案检查的覆盖和缺口

运行 `python -B docs/mainline1/contracts/validate_examples.py` 使用当前已安装 jsonschema 4.26.0；不安装依赖、不导入业务模块、不连接数据库或模型。Schema校验严格必填/可空/类型/枚举/额外字段/日期UUID格式；附加检查只覆盖脚本列出的有限一致性断言。

正常样例/partial/冲突/取消/解析失败/未知分母/manual/事件；拒绝样例包括字段缺失、零基列、未知操作、人工伪detector、假进度、语义缺失却complete、区间越界、重叠操作、跨域、自确认、未校准概率、复核拒绝冒充误报。资产变更/复核后旧计划/政策改变/删除必须产生相应拒绝码。

第2步单独未验证业务行为；本轮已验证合成CSV/XLSX实际字节解析、内部指纹/映射及隔离PostgreSQL事务/租约/并发，详见下表。仍未验证生产服务鉴权、公共hash跨语言等价、缓存与清理、真实事件投递、执行方、模型识别和UI。examples中的hash是明确合成占位，不能用来声称计划hash算法已实现。上述A01—A27在对应后续步骤补充实际验证证据。
