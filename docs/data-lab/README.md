## 路由与权限

- 学生页面 `/data-lab`；教师页面 `/data-lab/teacher`，登录+教师角色门禁。
- API 前缀 `/api/data-lab/`，所有视图 `no-store, private`。
- 学生领取后才能读材料；尝试/扫描/画像/回放/证据/提示均以当前学生归属重新校验。
- 教师列表、状态修改、帮助、材料附件要求角色 **且** CasePackage owner/teachers 对象授权。教师材料为 `teacher/cases/<task_key>/material/`，与普通详情分离，不由前端加载。
- 暂停只阻止新领取；撤回阻止新增材料读取和操作，但不删除已有证据。
- 没有下载保护副本、分享或执行 prepare/claim/consume 路由。

## 确定性教学流程

1. 保存实体类别、个人信息属性、分类分级三个不同结论及事实/依据卡引用。
2. 受限 Linux 子进程解析登记的合成 CSV 并调用 mainline1 原规则；客户表只扫描前3列但解析完整4列，日志扫描4列。字符按 Unicode 码点；CSV 逻辑行包括表头。
3. confirm/correct/false_positive/add_manual 使用原 ReviewService，教学账本隔离、CAS、同事务事件。新扫描不继承人工结果。原始候选、补录、复核后数量分列。
4. A1 mask；A2 deny；A3 defer；A4 50→51次为 mask→require_approval。每次10条与次数分开；B-v1 为 draft。先存学生建议，再揭示冻结的程序建议。教师参考画像不冒充学生检测覆盖。
5. 服务端保存证据快照，使用专用证据上下文交模块六；同键异内容拒绝。程序检查精确位置+类别、判断与只读证据；文字说明由六的人工必评量表处理。
6. 六的 SubmissionSnapshot、VerificationResult、ManualReviewTask 与一的 VerificationFact 是真实本地数据库记录；四不另建成绩表。失败 notice 保留冻结 payload，可重试，不重复计分。模块七/八通知仍为 not_connected。
7. 预置提示请求不等于展示；1—4层逐层展开，展示才记受助。教师帮助注明层级；同题旧解析暴露不因新尝试而清除。没有 AI 提示入口，不伪造 AI 帮助来源。
8. 复盘与分配使用模块六；新日志场景有独立材料、验证器与授权接收者。自动测试的到期时刻为模拟，不代表观察到三天后学习效果。

## 恢复与对账

- 请求出错保留幂等键与原内容，不能用改过的内容重放旧键。
- 扫描墙钟限制6秒；进程/最后事件事务丢失后，30秒以上 running 记录在下次扫描请求中转为失败。旧键不重跑，新键创建全新扫描；旧 worker 不得覆盖终态。
- 证据先持久化，六交接另用事务。六事件失败回滚六的半成品，四的证据保留待重试。先处理已有未交接证据，避免首次有效提交顺序变化。
- M1 事实和事件使用有界ID、固定时间与严格内容对比；notice status=sent 才表示本地接收确认。核验失败不记知识错误或通过。
- 本轮没有部署异步后台对账服务；由学生重试接口或运维调用 `deliver` / M6 notice retry 恢复。
