# 数据保护实际接入说明

日期：2026-11-13。

## 本次实现

删除了 `/privacy` 介绍页、路由和导航入口。数据保护接入原有资料、对话、记忆、访谈、考试、法律分析、文件上传下载和导出业务；原业务页面保留基于实际存储核验的状态反馈。

常规启动默认绑定运行时字段加密适配器。新建或更新受保护记录时，敏感内容写入经过认证的加密封装，原始字段列清空；业务在原有权限范围内显式解密读取。历史明文记录可以继续读取，正常保存时完成该记录的加密转换，也可通过维护命令集中迁移。

| 保护对象 | 已接入的实际行为 |
| --- | --- |
| 邮箱 | 邮箱加密保存，使用带密钥的索引支持精确查询；历史记录与加密记录的查询保持原有授权范围。页面按现有策略脱敏，空白或展示用脱敏值不会覆盖真实邮箱。 |
| 对话与 AI 记忆 | 对话正文、消息扩展元数据、长期记忆内容及其扩展元数据加密保存。对话和记忆沿用原接口的账号权限校验，显式解密并脱敏展示；历史签名校验函数也已兼容密文字段。 |
| 入学访谈 | 访谈回答、画像报告中的原始访谈快照加密保存；分析摘要及报告分析数据脱敏。多次提交回答时保留已保存的原始答案。 |
| 考试答案 | 用户提交答案加密保存，评分及授权读取使用现有受保护字段接口。 |
| 法律分析 | 分析原文、报告正文及人工备注加密保存；标题、摘要、分析元数据和错误信息等按策略脱敏。 |
| 私有文件 | 资源文件、封面与反馈附件采用私有加密存储。上传内容通过内存处理后加密落盘，下载、封面读取和预览经过原有对象权限校验；公开媒体服务排除这些私有命名空间。 |
| 受控导出 | 法律报告实际生成脱敏后的 TXT 文件，服务器仅保存加密文件，并在下载时重新核验权限、有效期及文件完整性。资源导出继续使用既有来源、目标、风险审批和交付校验链。 |

字段保存还处理了局部更新和失败重试：`update_fields` 未包含的待保存敏感修改会保留，后续保存仍加密；加密或数据库写入失败时保留调用方的待保存值。直接批量修改受保护字段会被拒绝，版本检查与实际写入使用同一数据库事务。

## 默认启动与持久密钥

常规部署使用以下设置：

| 设置 | 默认行为 |
| --- | --- |
| `DATA_PROTECTION_ENABLED` | 常规启动默认 `true`；隔离测试默认不自动绑定部署密钥，由测试提供独立适配器。 |
| `DATA_PROTECTION_ROOT` | Windows 默认为 `%LOCALAPPDATA%/ctf-platform/security`；未提供 `LOCALAPPDATA` 时使用用户目录下的 `.local/share/ctf-platform/security`。 |
| `DATA_PROTECTION_KEY_FILE` | 默认为 `DATA_PROTECTION_ROOT/storage-v1.key`，可配置独立持久路径。 |
| `DATA_SECURITY_CONFIG` | 配置后继续使用既有正式适配器及审批链，运行时适配器不替代该配置。 |

运行时采用 AES-GCM 认证加密，每次加密使用随机 nonce，并将对象、字段及版本等上下文绑定到密文。邮箱索引使用独立的密钥材料。密钥不从 Django `SECRET_KEY` 派生。

密钥目录必须位于源码和公开媒体目录之外，并满足当前服务账号的私有权限。Windows 使用原生私有 ACL。首次启动先完整写入私有临时文件，再独占发布最终密钥文件，支持多个 worker 同时首次启动。重启复用同一密钥；初始化标记已存在但密钥丢失时停止读取，不自动生成替代密钥。

Docker Compose 增加 `protection-data` 命名卷，挂载到 `/var/lib/ctf-platform`，并设置 `DATA_PROTECTION_ROOT=/var/lib/ctf-platform/security`。容器重建后继续使用卷内密钥与密文。部署备份需要保留对应持久密钥，才能读取数据库封装、私有文件及迁移快照。

## 历史数据盘点与迁移

以下命令供实际部署时在后端目录、使用目标环境配置执行。本地重启已完成数据库结构迁移；历史字段和已有业务文件的集中加密转换尚未执行。

先完成模型结构迁移，再盘点当前历史字段和文件；盘点不修改业务记录或文件：

```powershell
python manage.py migrate
python manage.py protect_existing_data --files
```

执行集中转换：

```powershell
python manage.py protect_existing_data --apply --files
```

也可只盘点或迁移指定模型的字段；`--model` 可以重复指定，其筛选不影响另行传入的 `--files`：

```powershell
python manage.py protect_existing_data --model users.CTFUser
python manage.py protect_existing_data --apply --model users.CTFUser
```

未指定模型时，命令扫描所有已接入 `ProtectedModel` 的业务模型。字段迁移按行锁定并执行事务，先将完整原始行序列化为加密快照，保存到 `DATA_PROTECTION_ROOT/migration-backups/<批次>/`，完成文件落盘后再转换业务记录。迁移后从数据库重新读取，核对解密结果和原始列清空状态；备份或核验失败时该行不提交。快照供维护恢复使用，内容不会以明文写入备份目录。命令返回各模型的历史数量、迁移数量及本次快照目录，重复执行会跳过已经完成转换的记录。

文件迁移保留数据库中的文件名引用，先生成并认证加密副本，再核对原始内容；验证一致后才删除对应旧明文文件。失败时保留原文件，并返回缺失或失败计数，便于修复后重跑。旧文件在转换前仍通过鉴权业务接口读取，不经公开媒体路径提供。

上述快照流程属于维护命令的集中迁移；正常业务保存时的单条历史记录转换仍遵循原业务事务。

## 法律报告与资源导出

法律报告导出入口现在生成真实文件。具备导出权限的管理账号必须同时处于该报告的可见数据范围；服务端解密报告正文，在内存中对标题、摘要和正文脱敏后生成 UTF-8 TXT，再将加密文件保存到私有目录，并写入导出记录及审计。只有实际保存并读回核验成功后才更新导出状态。

法律导出记录有效期为 24 小时。下载仅限发起账号，且每次重新查询账号状态、当前角色、报告可见范围和课程授权，同时验证策略版本、密文认证、长度及内容哈希。授权撤销、记录过期、文件被篡改或不可读取时不提供内容。导出记录页根据实际文件验证结果显示是否可下载，下载响应禁止缓存。

资源受控导出仍依赖既有正式配置和来源、目标、风险审批链。本次没有自动登记来源、创建授权或批准风险，也没有将未配置的资源导出默认开放。法律常规运行时导出在正式模式下不作为另一条可绕过审批的入口。

## 本地重启记录

2026-11-13 按用户要求重启本地项目。前端运行在 `http://127.0.0.1:5176`，后端运行在 `http://127.0.0.1:8000`。本地启动脚本为 `.state/local-dev/run-backend.py`，读取项目 `.env`，并配置前端端口的 CSRF 信任来源。

现有 SQLite 数据库位于源码仓库上一级的 `database/db.sqlite3`。重启前先生成并验证加密数据库快照，再应用 `feedback_center.0004_runtime_private_storage`、`legal.0004_report_exports`、`resources.0007_runtime_private_storage` 三项结构迁移。运行时加密已启用，待执行的结构迁移为零；未执行历史数据的集中转换。
